# R7.1｜独立论文科学议程整合（候选实现）

状态：独立 PR，等待 CI 和科学质量实验验证。**未调用付费 DeepSeek，未改历史 A/B 报告。**

## 问题和目标

原 R7.0 可生成 1–5 条研究路线，但难以判断是否组成一篇逻辑完整的下一篇论文。
R7.1 的新增输出是最多两条研究议程，每条由一个中心科学问题、真实论文事实引用、
2–4 个相互支撑的研究环节、竞争机制、整体否证条件及规划决策贡献构成。
论文研究范围扩大或方法更新都不是创新性认证。

## 实施与安全

- 在现有 `research_redesign` 调用中新增 `research_agendas`，无单独模型调用。
- 在现有 `independent_critic` 调用中新增 `agenda_reviews`，可全 HOLD/REJECT。
- 强制校验 route IDs 与原文已核实 fact IDs，禁止编造证据；要求区分机制和互补论证环节。
- 缺失结构、事实或审稿时不得进入临时人工评审名单；允许返回零条议程。
- 人工评审前的暂定状态仍**不表示**创新性、可行性、规划学价值或投稿机会已获认证。
- `pipeline_sha` 纳入新增模块；已冻结的旧版本实验不得用新代码静默恢复，须新建 A/B 对。
- 运行时结果记录 generation/review/audit，保留原路线输出、原审稿与源引用。

## 工程验收（在 PR CI 中进行）

新测试覆盖事实引用造假、无效路线、缺少机制环节、不完整审稿、缺失 A/B 规划文献、
允许零议程、超出数量/重复 ID，以及事实不支持时不推荐。现有完整测试套件须无回归。

## 科学质量验收（尚未完成）

2. 对相同来源和冻结证据分别运行历史 R7.0 与 R7.1（若需比较，须单独制定版本公平协议，
   不得把不同 pipeline_sha 强行视作同一冻结 A/B）。
3. 盲评重要性、真实先例差异、竞争机制、论文完整性、可行性；

4. 允许“不推荐选题”。不能因测试通过而宣布科研能力已实际提升。
