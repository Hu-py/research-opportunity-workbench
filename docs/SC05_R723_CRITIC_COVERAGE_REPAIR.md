# R7.2.3：独立审稿完整性故障的保守处理

问题来自真实完整实验：R7.2.2 采用已核实的同论文冻结事实，在经过文献评估、路线生成等步骤后，gate-off 第6次付费模型返回的 `reviews` 没有覆盖所有研究路线，原版 `critique` 因 `Critic must cover each route` 终止，造成报告缺失；此为**技术错误而不是科研价值验收**。

修复原则：**宁可把未评的路线暂缓，不把它自动评为成功。**

- 完整且合法的独立审稿继续严格按旧版 `critique` 原样处理；无行为改动。
- 不完整的审稿里，所有合法、可审核的真实模型评论仍保留；引用不存在的路线、重复或结构不正确的评论隔离并计数。
- 未被实际评论覆盖的路线补一个**标为系统自动保守HOLD**的占位审查，不伪装为模型独立审稿；不支持科研价值认证。
- 输出增加 `critic_completion_audit`、`review_origin` 和质量警告，准确区分“完整原模型审稿”与“缺失后的安全降级”。
- 新版本使用新 pipeline_sha；不篡改之前 R7.2.2 失败检查点。
- 可复用 R7.2 已逐字核验的论文事实进行新配对、减少重复付费提取，但这不构成未见论文独立验证。

验收：所有 CI 通过；在新完整流程中看到 gate-off 和 gate-on 两份正式报告后才对科研质量、直接文献与人工讨论研究主线进行盲评并决定下一轮是否需要继续优化。
