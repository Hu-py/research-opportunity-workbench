# Development Studio · Isolated PostgreSQL API E2E (2026-11-14)

Scope: validate real FastAPI permissions and PostgreSQL persistence without changing existing Render services or their production database tables.

## Source and separation

- Source branch: `experiment/devstudio-postgres-e2e-20261114`, based on integrated PR #63 commit `7e7921d020398c23b4164b4e2394ce7c275efd10`.
- Render Blueprint: `.render/devstudio-e2e.yaml` with `existingResources=create_new` and `autoSync=false`.
- New service name: `research-atlas-devstudio-e2e`; plan `free`; Singapore region.
- Existing managed PostgreSQL instance: `research-atlas-test-db` (not provisioned or adopted by this Blueprint).
- Dedicated schema: `atlas_devstudio_e2e_20261114`; startup creates and verifies schema and `PGOPTIONS` search_path before any app bootstrap.
- `DATABASE_URL` references the existing test database via Render `fromDatabase`. No password is committed, retrieved, or printed.
- `API_BEARER_TOKEN` is generated by Render. `TEAM_AUTH_ENABLED=true`, `APP_ENV=production`, and `WORKER_MODE=queue`.
- Unauthenticated `/api/health` may return a non-sensitive health response; authenticated DevStudio endpoints cannot be accessed without server token and team session.
- No changes to Vercel's `BACKEND_URL`; the production site continues using its current backend.

## On startup (only in the dedicated schema)

1. Abort if `DATABASE_URL` is missing or does not target database `research_atlas_test_db`.
2. Abort if the opt-in flag, bearer token, or team authentication is missing.
3. Create dedicated schema if missing and set `PGOPTIONS` for all subsequent API connections.
4. Confirm `current_schema() == atlas_devstudio_e2e_20261114` before creating any test account.
5. Use generated ephemeral identities and passwords (never print them); run FastAPI TestClient tests against the real database.
6. Verify unauthenticated request returns 401; viewer write returns 403.
7. Create one experiment as researcher, read it through a fresh GET and a separate SQL session, append one explicitly unverified CI run reference and a human evaluation, read lineage and audit.
8. Print sanitized PASS or fail startup; then launch the same FastAPI app **in the same process**, retaining schema isolation.

## Stop conditions and limitations

- This is a test schema inside an existing **test** Postgres, NOT a distinct database instance; the role must have CREATE SCHEMA permission.
- The startup test proves DB commit and cross-session persistence at that point. It does not independently verify a browser login via Vercel; that requires a separately authorized follow-up integration.
- Deploy, schema creation and tests are intentionally not run until the plan is reviewed and approved. Backend source commit must be checked before deployment.
- Existing test instance is on Render's free plan; test schema consumes some of its storage. Do not keep the extra service live longer than necessary.
- Never enable or point the production Vercel proxy at this test service.
