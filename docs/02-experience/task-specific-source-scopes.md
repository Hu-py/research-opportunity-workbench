# Research Atlas · 按科研任务分离期刊清单（V1.0 补充）

**决策日期：2026-11-22**
**原则：统一来源总目录，不统一所有任务的检索范围。**

## 为什么要区分

“来源总目录”是可以被多个科研场景引用的学术元数据：期刊或会议的标准名称、别名、所属学科、OpenAlex Source ID、状态和审核信息。

“任务专属来源清单”是不同研究任务对这个总目录的独立引用。它不改变来源本身，不应将三个任务的期刊强制合并，也不应通过全局启用一个期刊就把它加入所有任务。

## 用户端页面位置

- 一级导航不变：对话 / 研究台。
- **研究台 → 研究设置 → 任务期刊清单**：SC01、SC02、SC03 三套独立配置，分别选择 A/B/C 来源。
- **研究台 → 研究设置 → 来源总目录**：统一维护期刊、会议、标准名称、领域标签、来源核验。
- **研究台 → 研究设置 → 关注主题**：历史兴趣分支及其独立检索词；其旧版 \`venues\` 仍然是观察标签，不得冒充正式的严格来源约束。
- **对话 → 深度研究 → 本次文献来源**：沿用 SC03 默认清单，或者只为这一次临时覆盖；不修改 SC01/SC02 配置。

## 默认分类（可独立编辑）

| 来源类别 | 功能 | 初始候选 |
| --- | --- | --- |
| A 应用场景 | 规划问题、研究实践、应用需求 | Cities; Sustainable Cities and Society |
| B 前沿视角 | 城市理论与城市计算中的问题重构 | Environment and Planning B; Computers, Environment and Urban Systems |
| C 技术方法 | 计算机领域可迁移的方法增量 | NeurIPS; ICML; ICLR（初始候选，可按科研需要扩充或替换） |

这些来源作为“当前建议”，**不会因为出现在列表里就自动证明学术质量或自动开启严格限制**。组内可以自行增删、从全局目录选择并进行 OpenAlex 核验。

## 场景区分与权限

| 场景 | 保存范围 | 默认编辑权限 | 实际运行 |
| --- | --- | --- | --- |
| SC01 团队周报 | 团队一份 | 管理员 | 团队周报扫描严格使用该场景清单 |
| SC02 个人周报 | 每个成员独立 | 该成员 | 个人周报执行链路尚未接入，来源设置不等于个人周报已可运行 |
| SC03 定向科研任务 | 团队一份默认清单 + 每次任务独立快照 | 管理员管理默认清单，研究成员可创建单次覆盖 | Research Agent 在任务快照限定的期刊中查找文献 |

在旧单人认证模式下不允许写入假“个人专属”配置；SC02 需要成员级身份。

## 严格来源约束及证据边界

1. 默认清单是可见的建议配置；只有用户保存并明确开启 **严格模式**，后续对应任务才受限制。
2. 严格模式使用 **OpenAlex 精确 Source ID** 检索；来源未核验或已停用时**中止任务并提示**，不能默默扩大到所有期刊。
3. A/B 用于应用问题与规划视角检索；C 用于技术方法检索。SC03 使用当次快照选定的全部来源限制文献工具调用。
4. SC01 在严格模式下不能把其它主题监测、全局 Radar 历史结果混入本期受限报告。团队已核实的既有成果可作为研究背景，但不应误作限定期刊中的新文献。
5. 每个任务在入队时冻结当次配置版本和选中来源；后续编辑默认配置不会重写历史快照。
6. 同一期刊可属于多个科研场景，但一个场景里的 A/B/C 三个层次不应重复。
7. 论文元数据仍可在共用数据库中去重；“共用存储”不等于“每个场景都采用同一来源”。

## 当前实施边界

- Next.js V1.0 对任务清单分别呈现、读取、保存和选择单次覆盖。
- FastAPI 新增 task-source-scopes 管理接口及 task source snapshots 数据表；已有来源表原样保留。
- 新版本 Worker 对 SC01/SC03 的严格来源进行执行约束，未核验不运行。
- **必须同时部署兼容的 FastAPI 后端和 Next.js 前端后，新增设置才可真正保存和执行。** 仅有 Vercel 预览部署时，该入口明确显示后端尚未接入，不把演示当作真实功能。
- SC02 个人周报生成、定时和独立报告归档仍然单独排期。
- GitHub 公开 Radar A/B 元数据采集器及旧 watchlist venues 是不同数据渠道，尚未完全统一到当前任务配置链路，后续需独立验证映射和来源覆盖；不宣称其已被这些设置即时控制。

## 验收要求

- 仅修改 SC01 时，SC02 和 SC03 的配置、来源引用、历史报告均不变。
- SC03 指定单次来源后，修改默认清单不改变这次任务记录。
- 未核验的期刊在严格模式下不得触发无来源限制检索。
- SC01 严格模式下，不混入不属于该场景的文献和兴趣分支。
- 未部署后端 API 时界面不能假装保存成功。
