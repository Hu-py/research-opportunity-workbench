# Research Opportunity Skill V1.0 — 能力规范、执行工作流与报告模板

> **状态：升级草案 V1.0｜2026-11-22。** 本文与 [ChatGPT Space 规范页](https://chatgpt.com/space/page_cab2ba222c0c81919f5ec6f6508d84e3) 对齐。当前 PR 仅将规范和 Skills 版本化并接入有限任务适配器；不代表完整三源科研工作流已在生产部署或通过科研质量验收。

## 1. 设计判断

共享空间已经明确 L0–L3、A/B/C 三源、证据链、方法迁移、创新审查和报告要求。此前的 Research Opportunity Skill V0.1 只是迁移桥接说明，未完整承接这些要求。性能提升不能只靠扩写 Prompt，必须同时建设：

1. 可执行的科研指令与专业 Skills；
2. 受控的文献来源与真实检索能力；
3. 跨论文综合、方法迁移和最近邻审查工作流；
4. 统一报告模板与结构化结果；
5. 自动化测试和固定案例科研质量评测。

## 2. 必须分开的四套维度

| 维度 | 定义 | 使用规则 |
|---|---|---|
| A/B/C 来源组 | A 规划应用；B 城市科学与问题重构；C 计算机科学与技术方法 | 来源归属，不是质量等级；允许一篇论文属于多个组 |
| L0–L3 分析深度 | L0 检索覆盖；L1 跨论文专题；L2 选择性单篇深读；L3 可选研究行动/选题 | 深度层级；L2/L3 可以为空 |
| 旧 Radar A/B1/B2 | 历史科研雷达业务分类 | 保留历史语义，不得改名后冒充新 A/B/C |
| 选题等级/审核状态 | 候选质量和人工审核状态 | 与来源组、阅读深度分离；AI 不自动批准 A 级或正式发布 |

## 3. 场景与边界

- **SC01 团队科研周报：** 以三源 L1 综合专题为主体，L0 说明覆盖，L2 只深读少数代表论文，L3 仅在出现真实行动机会时产生。不得为凑数量强制生成选题或跨学科组合。
- **SC02 个人画像周报：** 只使用明确授权的个人画像和可见共享证据；画像不足时说明个性化依据不足，不推断私人兴趣。
- **SC03 临时定向科研任务 / UC01 跨学科科研选题：** 从具体研究问题出发，完成论文理解、文献对照、方法迁移、最近邻审查和选题构建。输出研究方案，不执行真实数据实验，不伪称已经下载数据或运行模型。

Research Atlas 的职责是科研发现、证据分析、方法迁移、研究设计和知识沉淀；不是代替研究者执行真实数据实验，也不是把任意模型名称组合成选题。

## 4. 文献来源与检索硬约束

1. 运行前读取当前启用的 Academic Source Registry / A-B-C source plan。核心证据必须来自已登记、启用且身份已核验的期刊/会议。来源未解析时不得静默退回无约束全库搜索。
2. A、B、C 三组分别检索和报告。允许一篇论文多组归属，但必须保留每个归属的来源依据。不得用标题关键词把未知期刊自动归入核心来源。
3. 来源目录是受控优先范围，不是论文质量自动判定器。目录外论文只有在其为必要理论基础、直接最近邻或关键反例时才作为补充证据；必须标注“目录外补充”，不得混入核心来源统计。
4. 期刊论文、正式会议论文、预印本、会议摘要、书籍章节、更正和社论分开标记。预印本不能自动视为已录用会议/期刊论文；同一研究不同版本应关联去重。
5. 保留题名、作者、年份、venue、DOI、稳定 URL、OpenAlex/出版方 ID、检索日期、来源组和证据等级。来源身份不明时标记 `identity_unverified`，不得进入已核验最近邻集合。
6. 检索必须有覆盖报告：查询式、来源范围、时间窗、返回数、分页/上限、无结果来源、摘要缺失、失败原因和补检情况。采样上限不等于完整召回；单次命中不等于检索覆盖充分。

## 5. 证据链与断言类型

每条重要断言必须区分：

- `paper_fact`：原文可核事实；
- `author_claim`：作者主张；
- `cross_paper_synthesis`：跨论文综合；
- `research_hypothesis`：系统提出的假设。

证据级别限定为 `metadata`、`abstract`、`full_text`。没有全文时不得声称已核实全文方法、实验或局限。

- 每条关键论点必须关联真实论文 ID、DOI 或 URL；需要时同时列支持证据与反对/竞争性证据。
- 一篇论文只能形成 `single_paper_observation`，不能包装成领域趋势；多篇同期论文只能称为 `multi_paper_observation`；只有有明确历史基线、时间窗和分母时才可称 `historically_compared`。
- 作者声称“首次”或“显著优于”不等于系统确认创新或突破；必须与直接最近邻和适当基线对照。
- 没有检索到近邻论文不等于不存在近邻研究；检索范围不足时，创新状态必须为 `unverified`。

## 6. SC03 / UC01 标准执行流程

1. **任务解析：** 明确研究对象、核心问题、目标结局/构念、空间与时间尺度、投稿/交付目标和已知限制。只有影响结论的关键缺口才向用户追问。
2. **原论文解剖：** 提取研究动机、问题、构念、数据、分析单位、方法机制、输入/输出、基线、结果、作者声称贡献、局限和未回答问题；逐项注明证据等级。
3. **研究诊断：** 区分原文明确承认的局限、由结果推导的解释和系统假设。保留原研究主线，不把局部技术细节直接升级成新论文问题。
4. **三源检索：** A 找同一规划问题及应用证据；B 找城市科学概念、测度、尺度和机制重构；C 找可迁移计算方法、理论或评测机制。每条检索路线说明要发现什么。
5. **书目与关系核验：** 将文献标为 `direct`、`indirect`、`counterexample`、`unlinked`。间接关联必须说明机制桥梁；反例必须说明挑战了哪条主张。容器记录、预印本版本和同一论文不同入口不得重复计数。
6. **方法深读与迁移：** 对关键 C 类方法解释机制、输入、输出、训练/推理条件、数据需求、假设、评价和计算成本；与 A/B 场景逐项匹配，指出必要改造和不能迁移的边界。
7. **跨路线综合：** 比较候选路线的共同问题、互补机制、冲突和证据缺口；优先形成一个有主次、有机制链条的主线，而不是并列罗列小点。
8. **最近邻与反向审查：** 对主候选检索最接近的 3–5 项工作，比较问题、对象/尺度、数据、方法、结局、贡献和未解决部分；主动寻找能够推翻候选主张的论文或反例。
9. **选题收敛：** 最多输出 1 个主选题和 2 个备选；证据不足时允许不给主选题。每个候选说明为什么值得一篇论文、真正增量、最低验证路径和停止条件。
10. **交付与追溯：** 保存输入快照、检索来源、论文集合、Skill/Prompt 版本、模型、工具调用、阶段状态、输出、人工评审和变更原因。未实现或失败阶段必须如实标记，不得人工补写成已执行。

## 7. “足以支撑一篇论文”的研究价值门槛

候选选题至少回答：

- **问题重要性：** 是否回应规划/城市科学实质问题，而非只对一个模型或变量做局部改动？
- **科学缺口：** 是否涉及新的构念、机制、识别策略、外部验证、尺度关系、理论解释或治理问题？缺口是否由最近邻对照支持？
- **实质增量：** 是否超越换城市、换算法、换数据集、增加一个特征或简单拼接两个方法？如果只是工程优化，应明确降级为技术改进。
- **机制与可证伪性：** 是否提出清楚的机制桥梁、核心假设、竞争解释和可以失败的验证设计？
- **可推广意义：** 结果能否对更广泛研究问题、规划决策或方法适用边界产生解释，而不只是单个案例描述？
- **可行性：** 数据权限、空间/时间粒度、样本、标注、基线、评价指标、资源和时间是否有可核查路径？登记数据资产不代表已获得原始数据或使用授权。

若核心贡献只是“把某模型用到某城市”，或无法说明最近邻差异与科学机制，结论应为 `HOLD` 或 `REJECT`，不为迎合用户强行给出创新选题。

## 8. 方法迁移必须输出的映射

| 环节 | 必须回答的问题 |
|---|---|
| 城市问题瓶颈 | 当前研究到底缺少什么解释/测量/预测/决策能力？ |
| 方法能力 | 来源方法真正解决什么技术问题？ |
| 机制桥梁 | 为什么该方法能力能解决目标瓶颈？中间假设是什么？ |
| 输入/输出 | 原方法需要什么输入、产生什么输出；目标场景是否提供对应变量？ |
| 适用条件 | 数据量、标签、尺度、时序、空间结构、计算资源和模型假设是否满足？ |
| 必要改造 | 哪些模块、损失、结构、训练策略或评价必须调整？ |
| 对照基线 | 至少一个简单基线和一个有竞争力的领域基线 |
| 最小验证 | 最小数据、最小实验、评价指标、失败阈值和停止条件 |
| 不适用边界 | 哪些情形下该方法不应使用或可能更差？ |

禁止只写“可以使用 GNN/Transformer/LLM/World Model”。方法名称不是迁移论证；必须写出机制桥梁和可证伪实验。

## 9. 报告模板

完整可复用模板已拆分为 [report_templates Skill](../skills/report_templates/SKILL.md)，并由 [cross_paper_synthesis Skill](../skills/cross_paper_synthesis/SKILL.md) 负责 L1 综合。

### SC01 周报

1. 本期范围与主要结论；
2. L0 检索覆盖、来源构成、证据深度和统计口径；
3. A/B/C 各自的 L1 综合专题；
4. 少量 L2 深读（可为零）；
5. L3 研究行动/选题（可为零）；
6. 论文与技术来源索引；
7. 检索和证据审计附录。

正文按科研价值排序，不按论文逐篇堆砌。

### L1 跨论文专题

标题直接表达研究变化或尚未解决的问题。正文包括：为什么值得关注；核心 Gap 及证据状态；多篇研究出现的路线/测量/观点变化；支持证据、反例和分歧；对团队研究的条件性意义；推荐动作；代表论文及其证据角色。若只有一篇，标为单篇观察，不写成趋势。

### L2 单篇深读

使用 **Why / Gap / How / What's different / Does it work / Team fit / Next** 结构，注明证据边界和待核查内容。

### SC03 / UC01 最终研究机会报告

1. 一句话结论与建议等级：推进 / 小规模验证 / 补证据 / 暂缓；
2. 任务范围与证据边界；
3. 原论文主线：问题、对象、构念、方法、结果、真实局限；
4. 关键研究诊断：原文事实、作者主张、系统推断分别列出；
5. 文献证据地图：direct / indirect / counterexample / unlinked；
6. 候选路线比较：研究问题、理论/机制、方法、数据、最近邻、风险；
7. 主选题（最多一个）与备选（最多两个）：核心问题、假设、贡献类型、为什么值得一篇论文；
8. 方法迁移链：机制桥梁、输入/输出、必要改造和失效边界；
9. 最小可行研究设计：数据类型/可能来源、分析单位、基线、指标、验证、停止条件；
10. 最近邻创新审查：最相似工作、已解决/未解决、差异和未核验点；
11. 风险与下一步；
12. 参考文献与证据索引。

## 10. 质量评分与一票否决

沿用 R6 固定评测量表：原研究连续性 25%；真实研究增量 20%；文献与新颖性证据 20%；方法迁移合理性 15%；概念可行性 10%；范围纪律与不确定性 10%。每项 0–5 分，必须写证据和理由；无法评分时标记无法评分，不得猜分。暂定通过线 ≥75/100，且原研究连续性、文献与新颖性证据、范围纪律均 ≥3/5。

一票否决：虚构论文/DOI/来源；身份错误或把同一论文不同版本重复计数；摘要推断全文细节；单篇声称领域趋势；仅凭关键词建立方法关联；未做最近邻检索却宣称创新已证实；把设计方案写成真实实验；声称团队拥有未经核验的数据或能力。

## 11. 阶段状态与审计

每个阶段记录 `input → action/tool → output → evidence → status → cost/error`。状态限定为 `completed`、`partial`、`blocked`、`not_implemented`、`skipped_by_design`、`needs_human_review`。中间失败允许继续独立步骤，但最终报告必须保留缺口；不得用人工补写掩盖工具未执行。

每次运行冻结：任务范围、论文集合/快照、来源目录版本、检索时间窗与查询、模型和参数、Skill/Prompt 哈希、工具调用、输出和审核状态。改动必须进入回归评测；同案例比较必须保持论文材料与证据边界一致。
